### Clé de traduction

La clé de traduction NE DOIT PAS être créée à partir d'une variable, que ce soit dans une chaîne de caractères (`` t(`errors.${errorCode}`) ``) ou directement (`t(errorKey)`).

Elle DOIT TOUJOURS être une chaîne de caractères statique, passée directement à `t()`.

### Expérience de développement

On a souvent besoin de chercher dans la base de code où se trouve une clé de traduction spécifique.

### Analyse statique

Les outils d'analyse statique (comme [i18next-scanner](https://github.com/i18next/i18next-scanner)) peuvent être utilisés pour détecter les clés de traduction manquantes ou inutilisées dans le code.

Idéalement, on pourrait aussi valider avec TypeScript que la clé de traduction existe bien dans les fichiers de traduction.

:::

Si l'on a besoin d'avoir une partie dynamique dans la clé de traduction, il existe des façons de faire :

#### Utiliser un `select` ICU

```ts
return t('errors', { errorCode });
```

et dans l'éditeur de traduction:

```json
{errorCode, select,
  network {Erreur réseau}
  server {Erreur serveur}
  timeout {Délai d'attente dépassé}
  other {Erreur inconnue}
}
```

#### Utiliser un "switch"

```ts
switch (errorCode) {
  case 'network':
    return t('errors.network');
  case 'server':
    return t('errors.server');
  case 'timeout':
    return t('errors.timeout');
  default:
    return t('errors.unknown');
}
```

#### Construire la configuration avec des appels à `t()`

Quand les libellés sont utilisés dans une configuration (options d'un select, colonnes d'un tableau…), on construit cette configuration avec des appels à `t()`, plutôt que d'y stocker des clés :

```ts
const ERROR_LABEL = {
  network: t('errors.network'),
  server: t('errors.server'),
  timeout: t('errors.timeout'),
};

return ERROR_LABEL[errorCode] ?? t('errors.unknown');
```
