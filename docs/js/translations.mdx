### Clé de traduction

On NE DOIT PAS appeler `t()` avec une clé typée `string`, qu'elle soit construite par concaténation ou template (``t(`errors.${errorCode}`)``) ou lue dans une variable `string` (`t(errorKey)`).

La clé DOIT être écrite en entier dans le code : directement dans l'appel à `t()`, ou dans une valeur typée `TranslationKey`.

### Expérience de développement

On a souvent besoin de chercher dans la base de code où se trouve une clé de traduction spécifique. Une clé construite par concaténation n'y apparaît jamais en entier.

### Analyse statique

Quand `t()` est typé (augmentation de `CustomTypeOptions` d'i18next dans `types/global/i18next.d.ts`), TypeScript vérifie que la clé existe dans les fichiers de traduction. Il ne peut pas le faire pour une `string` : `t()` la refuse, et le cast qu'il faudrait pour la passer désactive la vérification.

Les outils d'analyse statique (comme [i18next-scanner](https://github.com/i18next/i18next-scanner)) qui détectent les clés manquantes ou inutilisées ne voient pas non plus une clé construite à l'exécution.

:::

Si l'on a besoin d'avoir une partie dynamique dans la clé de traduction, il existe des façons de faire :

#### Utiliser un `select` ICU

```ts
return t('errors', { errorCode });
```

et dans l'éditeur de traduction:

```json
{errorCode, select,
  network {Erreur réseau}
  server {Erreur serveur}
  timeout {Délai d'attente dépassé}
  other {Erreur inconnue}
}
```

#### Utiliser un "switch"

```ts
switch (errorCode) {
  case 'network':
    return t('errors.network');
  case 'server':
    return t('errors.server');
  case 'timeout':
    return t('errors.timeout');
  default:
    return t('errors.unknown');
}
```

#### Utiliser une configuration

Quand les libellés sont utilisés dans une configuration (options d'un select, colonnes d'un tableau…), deux formes sont valables.

On construit la configuration avec des appels à `t()`, là où `t` est disponible (dans le composant ou le hook) :

```ts
const ERROR_LABEL = {
  network: t('errors.network'),
  server: t('errors.server'),
  timeout: t('errors.timeout'),
};

return ERROR_LABEL[errorCode] ?? t('errors.unknown');
```

Ou on y range des clés écrites en entier, typées `TranslationKey` (exporté par le `i18n.ts` des paquets dont `t()` est typé). La configuration peut alors vivre hors du composant :

```ts
import { type TranslationKey } from '../i18n';

const ERROR_KEY: Record<ErrorCode, TranslationKey> = {
  network: 'errors.network',
  server: 'errors.server',
  timeout: 'errors.timeout',
};

return t(ERROR_KEY[errorCode]);
```
